# مرآة الأشعة التعليمية — حزمة Android مع تخزين دون اتصال

## ما الذي تغير؟
- الحفاظ على محرك العرض والميزات التشريحية والتتبع الأصلية.
- إضافة Web App Manifest للتثبيت على Android من Chrome بوضع مستقل.
- إضافة Service Worker يخزّن صفحة التطبيق وملفات التشغيل الخارجية (MediaPipe وWASM والنماذج والخطوط) تلقائياً عند تنزيلها أول مرة.
- إضافة مؤشر اتصال وحالة التخزين، وزر لفحص عدد الموارد المحفوظة.
- تحسين رسائل الأخطاء عند غياب HTTPS أو فشل تحميل المحرك، وإيقاف الكاميرا عند فشل التهيئة لتفادي بقاء مؤشر الكاميرا فعالاً.
- قصر اكتشاف الهاتف على Android لأن المنصة المستهدفة Android فقط.

## التثبيت على Android
1. ارفع محتويات هذا المجلد كاملة إلى استضافة HTTPS ثابتة (لا ترفع ملف HTML وحده).
2. افتح رابط `xray-mirror-v3.html` في Google Chrome على الهاتف.
3. وافق على تثبيت التطبيق من قائمة Chrome (تثبيت التطبيق / Add to Home screen).
4. افتح التطبيق المثبت وهو متصل بالإنترنت أول مرة.
5. اضغط «ابدأ الكاميرا» واسمح بالكاميرا وانتظر اكتمال تحميل النماذج الثلاثة: الجسم والوجه واليدين.
6. بعد ظهور التتبع، اترك التطبيق مفتوحاً حتى تكتمل طلبات الموارد. استخدم زر «فحص العمل دون إنترنت» لمراجعة عدد الموارد المحفوظة.
7. أغلق التطبيق، فعّل وضع الطيران، ثم افتحه من أيقونته واختبر التشغيل.

## حدود مهمة بخصوص Offline
هذه الحزمة تستخدم تخزين Service Worker للموارد الخارجية عند أول تنزيل ناجح. لذلك **لا يمكن أن يكون أول تشغيل بعد تثبيت PWA دون إنترنت**؛ يجب تشغيله مرة واحدة متصلاً لتنزيل مكتبة MediaPipe وملفات WASM والنماذج. بعد نجاح تنزيل كل الموارد، يفترض أن تعمل الميزات المعتمدة على هذه الموارد دون اتصال، ما دامت بيانات الموقع لم تُمسح ولم يحذف Android التخزين بسبب ضغط المساحة.

لم أتمكن في بيئة البناء هذه من تنزيل مكتبة MediaPipe وملفات النماذج من CDN لأن الوصول الشبكي الخارجي غير متاح. لذلك لم أضمّنها مادياً داخل الحزمة ولم أزعم أن التطبيق APK مستقل بالكامل. التخزين التلقائي يعتمد على نجاح استضافة تلك الموارد وإمكانية تخزين استجابات CORS في Chrome. للحصول على APK مستقل تماماً منذ لحظة التثبيت، يجب إدراج ملفات المكتبة وWASM والنماذج محلياً داخل أصول Android بعد تنزيلها من مصدرها الرسمي والتحقق من تراخيصها وبصماتها.

## اختبار الوظائف
- فحوص آلية منفذة: تحليل JavaScript المضمّن بواسطة Node.js، تحليل JavaScript الخاص بـ Service Worker، تحليل JSON للـ Manifest، وقراءة بنية HTML.
- فحوص ساكنة: التحقق من وجود نقاط التحكم الأساسية للتشغيل والكاميرا واللقطة والتسجيل والمعايرة والجولة والبحث والتخزين دون اتصال.
- غير منفذ: اختبار الكاميرا الحقيقية، دقة التتبع، FPS، التسجيل الفعلي، صلاحيات Android، وسيناريو وضع الطيران. هذه تتطلب هاتف Android ومتصفح Chrome فعلياً.

## تشغيل محلي للاختبار
يلزم HTTPS أو localhost حتى تسمح المتصفحات بالكاميرا وService Worker. من مجلد الحزمة:

```bash
python -m http.server 8000
```

ثم افتح `http://localhost:8000/xray-mirror-v3.html` على جهاز محلي/محاكي يدعم الكاميرا. لا تستخدم `file://`.

## ملاحظات الأداء
النسخة تحتفظ بآلية خفض الحمل الديناميكية الموجودة في المصدر. معدل الإطارات والدقة الفعلية يعتمدان على معالج الهاتف ومسرّع GPU وإصدار Chrome. لا يمكن ضمان «أقصى أداء» موحد لكل أجهزة Android؛ ابدأ بإضاءة جيدة وكادر يظهر الجسم كاملاً وأغلق التطبيقات الثقيلة.

## طبيعة التطبيق
هذا محاكاة تشريحية تعليمية تقريبية فوق صورة الكاميرا، وليس جهاز أشعة حقيقياً أو أداة تشخيص طبي.


## تحديث الهوية البصرية والأيقونات
- اعتماد هوية بصرية طبية تقنية باللون الكحلي والأزرق السماوي، مع رمز جسم بشري داخل حلقة مسح.
- استبدال أيقونات المشغّل بصور تشريحية عالية الدقة، وتوفير SVG متجهي واضح.
- إضافة أيقونات SVG موحّدة إلى أزرار الإجراءات ومناطق الجسم، مع حالات تفعيل واضحة وتحسين التباين واللمس على الهاتف.
- إضافة رمز بصري متناسق إلى شاشة بدء التطبيق.
